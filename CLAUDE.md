# CLAUDE.md - NorthernCrater Project Guide

## Project Overview
**NorthernCrater** is a macOS mod manager and launcher for *Final Fantasy VII* (Steam). The game runs as a **native Apple Silicon (arm64)** app built on the user's Mac from their own copy of the game. The whole repo is **GPL-3.0** (`LICENSE`). It has two parts:

*   **The app** (`NorthernCrater/`, Swift/SwiftUI): folder selection, mod list and load order, mod catalog, saves page, build and launch.
*   **The engine** (`engine/`): a vendored, modified copy of the macOS engine from GJ Materia (https://github.com/goodjoeth/gj-materia, commit `2b58834`), itself a macOS port of FF7Recomp (statically recompiled game + FFNx on bgfx/Metal). `engine/NOTICE.md` lists what was copied, left out and changed. The engine app is **"NorthernCrater Engine"** (`com.northerncrater.engine`) and has **no UI of its own**: it starts the game immediately and is driven by environment variables. NorthernCrater no longer needs GJ Materia's repository; the build still downloads ~20 pinned third-party repos (pcrecomp, FFNx, bgfx, SDL3, FFmpeg...).

## How the pieces fit
*   **Build** (`RecompilationService` -> bundled `EngineOverlay/build_engine.sh`): the app bundles `engine/` as a resource folder. The script rsyncs it to `~/Library/Caches/NorthernCrater/engine/src` (a path without spaces; their scripts break on spaces), creates a private Python venv (`capstone`, `pefile`), then runs the engine's `tools/build_mac.sh` (import game files, lift the exe to C, FFmpeg, Metal shaders, compile) and `tools/stage_game_mac.sh`, and checks the app bundle has its shaders. 15-30 minutes the first time; later runs are incremental. A lock allows one build at a time (exit code 75 = another is running).
*   **Play** (`LiveGameService`): refreshes the exe copy and data link in the game folder, writes the mod profile (`ModProfileWriter`), launches `NorthernCrater Engine` with `FF7_GAME_DIR` and `FF7_LOG_STDERR=1`; it always opens on the title screen (no start-mode menu: `FF7_QUICKBOOT` is never set, and removed from the environment if the app inherited it). Closing the game window quits it. Log: `Engine/last_run.log`.
*   **Mod profile**: the engine reads `<game folder>/../mods/profile.xml` (i.e. `~/Library/Application Support/NorthernCrater/mods/`, `AppPaths.modsDirectory`, lower case) and ignores `FF7_HOME` (only `engine/tools/ff7mod_mac.py` uses it). `profile.xml` lists mods in priority order (first wins) by file or folder name inside that folder, with `Enabled="false"` and `<Option ID= Value=>`. `ModProfileWriter` links each mod there and **never deletes a real file**: catalog downloads live in the same folder, a mod already there is referenced in place, name clashes get a `2-` prefix, and only stale symlinks are removed. The engine follows symlinks (`stat`).
*   **Mod import** (`ModManagerViewModel.importMods`): any number of `.iro` files and mod folders at once (toolbar "Add Mods" menu with the native `NSOpenPanel`, or drag and drop on the list); duplicates are skipped, failures are listed in an alert and never stop the rest. A folder mod is a folder with a `mod.xml`, or a wrapper folder around exactly one. `.7z`/`.zip` give a hint to unpack first. Reading lives in `IROArchive` (directory, LZS, LZMA entries), `LZMADecoder` (pure Swift; Apple's Compression cannot read these streams) and `ModInfoParser` (the real `<ModInfo>`/`<ConfigOption>` schema). Verified on 15 real mods (all parse, <100 ms each), the LZMA decoder byte-for-byte against Python on 51 vectors and the LZS decoder against the engine's C decoder on 300 streams.
*   **Mod detail** (`ModDetailView`), laid out like 7th Heaven's Configure window: option list on the left (a mod's heading options, one choice with no name, become collapsible groups), and on the right the selected option's description, choice picker (Toggle for plain on/off), a large picture of the chosen choice and a sound-preview button. Pictures: the mod's `<PreviewFile>` and each choice's `PreviewFile="…"` (paths inside the .iro or mod folder), loaded off the main thread by `ModPreviewStore` (an actor) as 900 px thumbnails and cached; animated GIFs show their first frame. Sounds: `PreviewAudio="…"` (only Symphonic Remasters has them: Ogg Vorbis, which macOS cannot play): `ModAudioPreview` converts the track with `ogg2wav` (`engine/tools/ogg2wav.c`, built on demand by the bundled `build_ogg2wav.sh` into `~/Library/Caches/NorthernCrater/engine/bin` from the libvorbis sources the engine build downloads, so it needs the engine built once) and plays the WAV with AVAudioPlayer; temp WAVs are cleared at launch. The archive readers (`IROArchive`, `LZMADecoder`) are `nonisolated` for this (the project defaults types to the main actor). Saved state older than `ModItem.currentInfoVersion` is re-read from the mods at launch to fill in previews and FFNx entries. Checked: 308/308 pictures of the 15 .iro mods and 67/74 of the Enhanced Stock UI folder (the 7 misses are `Previews\.png` paths with no file name, a mistake in that mod.xml).
*   **SwiftUI trap**: `.task`/`.onAppear` on a view that renders nothing at first (e.g. `Group { if let image { … } }`) never runs once it sits inside a stack, so a lazy loader hung there never starts (this hid every mod picture once). Anchor it on something always present (`ModPreviewImage` uses a 1 pt `Color.clear`). Real views can be rendered offscreen to a PNG for checking: host in `NSHostingView` inside an unshown `NSWindow`, run the main loop a few seconds, `cacheDisplay` into a bitmap (compile the view files with `swiftc -default-isolation MainActor`).
*   **Controls page** (`ControlsView`, toolbar gamepad icon): *Keyboard* edits the layout with `KeymapEditor` (press-a-key capture through a local `NSEvent` monitor; Command, F1 and Esc are reserved) and saves `KeymapStore` -> `~/Library/Application Support/NorthernCrater/keymap.txt`, which the engine reads at start (`[ff7] keymap.txt: 16 buttons`; one line per button, `name keycode...`, macOS virtual key codes < 128; a file with any valid line REPLACES the engine defaults, so all 16 buttons are always written, and the default layout deletes the file). *Controller* lists the pads (`ControllerMonitor`, GameController framework), tests buttons/sticks live and edits the analog options in `GameLaunchConfig` (stick dead zones, auto-run, camera inversion, analog movement -> FFNx.toml). Controller buttons are NOT freely remappable here: the engine maps them to fixed Xbox buttons (`ff7_platform_pad_state`) and the game's own Config menu assigns actions. The one engine-side option is "swap confirm and cancel" (`GameLaunchConfig.swapConfirmCancel` -> env `FF7_SWAP_AB=1` -> A and B exchanged on the controller only, not the keyboard; needs an engine built with that change).
*   **Saves** (`SavesView`, `SaveService`, `FF7SaveParser`): reads PC `saveNN.ff7` files (10 files x 15 slots; layout documented in `FF7SaveParser.swift`), lists the game's saves, imports a file into the first free slot (never overwrites) or opens one read-only. Uses the native `NSOpenPanel` (SwiftUI's `fileImporter` misbehaved inside the sheet). PC saves only, no memory cards.
*   **Locations** (`AppPaths`): engine build in `~/Library/Caches/NorthernCrater/engine` (rebuildable); game folder `~/Library/Application Support/NorthernCrater/Game` (saves in `Game/save`), run logs `.../Engine`, mods and the engine's profile `.../mods`, state `.../state.json`. Leftovers of earlier pipelines can be deleted: `Native/`, `Run/`, `BuildCache/`. The Steam install is never written to.

## Supported game install
Only **"FINAL FANTASY VII" (the new Steam release, folder `FINAL FANTASY VII Steam Edition` on disk)**: needs `ff7/resources/ff7_1.02/ff7_en` (SHA-1 `ac306ae92615af75ff36bba6347c67ca1284151d`) and `ff7/workingdir/data`. The **2013 Edition** (has `FF7_Launcher.exe`) is rejected with `ModManagerError.legacyEdition`: the lift and every FFNx patch are keyed to the 1.02 exe. 2013 saves (`save00.ff7`) are compatible.

## Tech Stack
*   **App:** Swift, SwiftUI. **App Sandbox is OFF** (runs `git`/`cmake`/`ninja`/`clang`, builds outside its container).
*   **Prerequisites:** Xcode Command Line Tools, Homebrew `cmake`, `ninja`, `python3`. Nothing is installed system-wide.

## Key Directory Structure
*   `NorthernCrater/` - the app: `App/`, `Views/`, `ViewModels/`, `Models/`, `Services/`. This folder is an Xcode synchronized group: **never put engine sources inside it** (they would be compiled into the app).
*   `NorthernCrater/EngineOverlay/build_engine.sh` - the build wrapper (bundled flat into Resources).
*   `engine/` - GPL-3.0 engine sources, referenced from the Xcode project as a folder reference and copied into the app's Resources.
*   `CREDITS.md`, `LICENSE` - credits and license.

## Changes made to the engine (full list in engine/NOTICE.md)
*   The SwiftUI launcher and its 7z/installer/icon support were removed; the product was renamed; `src/mac/ff7_mac_main.mm` starts the game directly and quits on window close.
*   `patches/ffnx/0002-time-module-guest-addresses.patch`: FFNx's day/night time module read raw guest addresses; with arm64's offset memory they need `GPTR()`, else any mod enabling `enable_time_cycle` crashed the game.
*   `macos/CMakeLists.txt`: keep `set(FF7_RES ...)` (it sat next to the icon lines once; removing it makes the post-build step try to create `/ffnx/shaders`).

## What the removed launcher used to do (the app must do it, or it is missing)
*   **Done:** `FFNx.toml` is written at each Play by `FFNxConfigWriter` from `Game/FFNx.template.toml` (the build's pristine default): first the settings screen (`GameLaunchConfig`: resolution scale, aspect, 60 FPS, analog), then the enabled mods' `<FFNxConfig>` entries whose option conditions hold (`<key Option="value">`; `<item>` children = comma list; higher mod wins). The engine does not read mods' FFNxConfig itself. `FF7_ASPECT` (0 4:3, 1 stretched, 2 16:9, 3 16:10, 4 21:9) is set from the same settings. Not yet written: the launcher's other settings (bilinear, vsync, music/sfx volume, language, FPS counter).
*   Write `fixes/data/lang-*/kernel/window.bin` and list it last in the profile (restores the `m M w W` glyph widths; skipped, so some text may look slightly different with mods).
*   Write `boosters.txt` (rumble, cheats, encounters, battle HUD), re-lift mods' code patches (`engine/tools/relift_mods_mac.sh`: without it, mods that patch game code run interpreted and battles are slow), mod `.7z`/`.zip` extraction (`engine/tools/ff7mod_mac.py`, `ff7mod-un7z`), catalogs/downloads, PS memory-card saves, achievements, iCloud saves.

## Known Issues and Notes
*   `.iro` files and mod folders import; `.7z`/`.zip` do not (unpack first). The engine ignores SIGTERM: a Stop button must ask it to quit, then force-kill.
*   A non-obvious Xcode trap: `NorthernCrater/` is a synchronized group, and edits that slice a file by finding the first occurrence of a name have garbled protocol/struct pairs twice; check the result.
*   Updating the engine means re-vendoring from GJ Materia and re-applying the changes in `engine/NOTICE.md`.

## Releases
`scripts/make_release.sh [version]` builds an arm64 Release (ad-hoc signed, no developer identity), verifies it and writes `dist/NorthernCrater-<v>-arm64.{dmg,zip,sha256}` (see `docs/RELEASING.md`). The download holds the app and the engine SOURCES only: never ship a built engine or game files. It is not notarized, so Gatekeeper rejects it until the user allows it (the README explains how). Updating the app does not rebuild the engine (the user presses Rebuild Engine).

## Logo
The app icon is `NorthernCrater/Assets.xcassets/AppIcon.appiconset/` (its files are WebP data named `.png`; Xcode accepts them). The README uses `docs/logo.png`, a real 512 px PNG copy so it renders everywhere. Refresh it after changing the icon: `sips -s format png --resampleHeightWidth 512 512 NorthernCrater/Assets.xcassets/AppIcon.appiconset/1024-mac.png --out docs/logo.png`.
